# 고정 상품 없는 종류별 API 추천 — 2026-11-12

## 사용자 요청과 현재 동작

이전의 고정 7개 제품 카탈로그를 제거했다. 운영 코드에 추천 제품명·브랜드 목록·상품번호를 미리 넣지 않는다. 테스트에 등장하는 가상 이름·상품번호는 네트워크 없는 검사 예시이며 운영 추천으로 사용하지 않는다.

| 화면 | 선택 가능한 추천 종류 | 선택 제한 | 선택했을 때 | 선택하지 않았을 때 |
| --- | --- | --- | --- | --- |
| 화장품 성분 분석 | 스킨·토너·에센스·세럼·앰플·크림·로션 | 최대 3종, 선택 사항 | 선택한 종류마다 서로 다른 제품 1개씩 | 허용 종류 중 최대 3개 |
| 모델링팩 | 에센스·세럼·앰플 | 최대 1종, 선택 사항 | 해당 종류 제품 1개 | 세 종류 중 최대 3개 |

모델링팩 종류 선택은 체크박스로 구현해 다시 눌러 전부 해제할 수 있고, 다른 종류를 누르면 이전 선택을 해제한다. 화장품에서는 네 번째 종류를 누르면 추가하지 않고 제한을 안내한다. 피부 고민 선택은 기존대로 유지한다. 스킨·토너를 동시에 선택하면 동일 상품을 두 번 내놓지 않는다. 확인한 제품이 없는 종류는 미확인으로 표시하며 다른 종류로 대신 채우지 않는다.

## 동적 추천 경로

1. 기존 전성분 판독·일반 기능 설명을 수행한다. 완전 판독의 실제 응답일 때만 제품 추천을 시작한다. 부분 판독·모의 응답·기존 요청 실패에서는 추천 API를 호출하지 않는다.
2. 사용자 피부 타입·선택 고민·판독된 성분·추천 종류를 Gemini에 제공한다. 사진·API 키·전체 원문·임의 요청 객체를 추천 프롬프트에 복사하지 않는다. 키는 Google 고정 엔드포인트의 헤더로만 보낸다.
3. Gemini의 **URL context**로 선택한 올리브영 스킨케어 카테고리 공개 목록을 읽어, 이 목록에서 현재 조건에 맞는 후보를 최대 12개 찾는다. 제품 자체는 고정하지 않는다. 고정된 것은 종류와 카테고리 입구 URL뿐이다.
4. 그 요청의 실제 `url_context_result` 성공 상태가 확인된 목록에서 찾은 후보만 다음 단계로 넘긴다. 각 항목의 `sourceListUrl`은 그 종류에 지정한 실제 조회 URL과 같아야 한다. 실제 JSON 실호출에서는 인용 주석이 빠질 수 있어 `url_citation` 유무를 필수 조건으로 삼지 않는다. 모델이 JSON에 성공했다고 쓰는 것만으로 통과시키지 않으며, Google의 도구 조회 메타데이터를 검사한다. 제품 링크가 있으면 정확한 올리브영 HTTPS 호스트·상품 상세 경로·상품번호 형식으로 제한한다.
5. 두 번째 요청에서 현재 페이지를 다시 읽고 본품명·브랜드·종류·분류·표시 문구를 재확인한다. 상세 링크가 실제로 노출되면 그 상세 페이지를 읽는다. 링크가 없는 제품은 원래 카테고리 목록을 재조회하며 `category_list`로 구분하고 **상품 상세 정보 미확인**을 표시한다. 이 후보는 본품명으로 만든 올리브영 검색 링크에 연결한다. 검색 링크는 상세 상품의 직접 링크가 아니다. 상품번호를 만들지 않는다. 원래 후보와 정체성·종류가 다르거나 재조회 실패·단종·품절·종류 불명이면 제외한다.
6. 선택한 종류를 채우는 수, 여러 고민과 연결되는 범위, 비교 후보 수를 기준으로 최대 3개 조합을 비교한다. 선택한 종류가 있으면 각 종류 최대 1개를 강제한다. 같은 조건은 API가 반환한 비교 순서를 사용한다. 전체 올리브영 재고의 전수 검색이나 개인별 효능의 최적화를 입증한 순위는 아니다.

현재 카테고리 페이지에 노출된 후보 범위에서 비교한다. 페이지 접근 제한·분류 체계 변경·API 오류 때문에 추천이 없거나 일부 종류만 나올 수 있다. 이 경우 과거 카탈로그나 모델 기억으로 만든 제품을 보여주지 않는다. 성분 분석 결과는 유지하고 추천 실패 사유를 별도로 표시한다. 목록만 읽은 추천 이유는 현재 제품명·수분/진정 등 표시 문구와 고민의 연결이며 전성분 검증 결과가 아니다.

## 제품 사진과 직접 링크

사용자가 상세 링크가 불가능하면 사진을 보여 달라고 추가 요청해 카드에 제품 사진 영역을 넣었다. 현재 페이지에 해당 본품과 연결된 이미지 주소가 실제 보일 때만 API가 반환하도록 한다. 두 번의 조회에서 같은 주소를 반환하고, 정확한 `https://image.oliveyoung.co.kr`의 goods/thumbnails 경로와 JPG·PNG·WebP 형식을 통과해야 표시한다. 파일명·상품번호로 이미지 경로를 조합하지 않는다. 사진은 공개 CDN에서 직접 읽고 키·리퍼러를 전송하지 않으며, HTML CSP도 그 이미지 호스트만 추가했다.

사진 주소가 없거나 로딩에 실패하면 **제품 사진을 확인하지 못했어요**를 표시하고 이름·추천 이유를 유지한다. 제품 선택 목록과 사진을 미리 고정하지 않는다. 브라우저 UI 검사에 사용하는 실물 사진 한 장은 별도 로컬 검사 폴더에만 있으며 운영 코드·ym·배포 묶음에는 없다.

**실제 API 검증에서는 추천 1건이 나왔지만 사진 주소는 null이었다.** 사진 표시 코드와 오류 처리는 검사했으나, 실제 추천의 사진 주소를 자동 획득하는 과정은 아직 성공하지 않았다. 현재 무료 Static + URL context 조건에서 사진이 항상 보인다고 안내하면 안 된다.

스킨과 토너는 올리브영의 같은 중분류에 있지만 요청에서는 구분한다. 본품명과 상품 정보에서 종류를 확인한다. ‘스킨1004’라는 브랜드명, ‘스킨 부스터 세럼’의 스킨, 증정 토너를 근거로 스킨/토너로 분류하지 않는다. 서로 다른 종류가 섞인 세트·복합 이름, 패드·마스크·클렌징·선케어·메이크업·헤어·바디·아이 전용 제품은 제외한다. 보수적인 본품명 검사 때문에 종류가 애매한 제품은 추천하지 않을 수 있다.

## 근거와 무료 프로젝트 조건

- Google 공식 [URL context 가이드](https://ai.google.dev/gemini-api/docs/url-context): 주어진 공개 URL 읽기, 응답 인용 및 조회 상태, 요청당 URL 수 제한을 확인했다.
- [Interactions API 레퍼런스](https://ai.google.dev/api/interactions-api): `url_context_result.result[].url/status` 및 `model_output`의 JSON 응답을 사용한다. 조회 성공은 개별 상품 문구의 독립 검증이나 사진 일치의 객관적인 보증이 아니다.
- [Gemini 3.5 Flash-Lite 모델](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite)과 [가격표](https://ai.google.dev/gemini-api/docs/pricing): 2026-11-12 확인 기준으로 이 모델의 무료 프로젝트와 URL context를 사용한다. 이 모델의 Google Search grounding은 무료 티어 대상이 아니므로 `google_search`를 활성화하지 않는다. 다른 유료 모델 전환·자동 재시도·별도 검색 서비스·외부 서버는 추가하지 않았다.
- 기존과 같이 결제 계정이 연결되지 않은 무료 프로젝트 키를 사용하도록 안내한다. 키가 속한 프로젝트의 결제 상태를 앱이 조회하거나 강제할 수는 없다.

카드의 상품 문구·제품 종류·추천 이유는 공개 페이지를 읽은 API의 해석이다. 도구의 조회 성공·출처 URL 연결·형식·종류 검사는 독립적인 성분/효능 검증을 대신하지 않는다. 가격·재고·리뉴얼 상태가 이후에도 유지된다고 보장하지 않는다. 사용자는 현재 구매 페이지의 라벨·용량·옵션·사용법을 다시 확인해야 한다. 모델링팩 직접 혼합은 계속 미확인이고, 혼합 금지를 선택하면 섞지 말라고 안내한다.

## 기존 팀 코드의 변경 범위

- `BeautyAI/index.html`: 두 화면의 선택 사항 종류 체크박스, 종류별 추천 수 안내, 동적 추천 상태 표시.
- `BeautyAI/style.css`: 종류 선택 영역·모바일 줄바꿈·카드 긴 이름 처리.
- `BeautyAI/script.js`: 선택 제한, 추천 호출, 로딩/실패/부분 추천 표시, 결과 복사. 기존 분석 요청의 엄격한 입력 규격과 섞이지 않도록 추천 종류는 별도 요청으로 보낸다.
- 신규 `BeautyAI/recommendation-client.js`: 고정 제품 없이 현재 목록/상품 조회, 출처/종류 검증, 사용자별 후보 선택, 오류와 키 보호.
- `BeautyAI/report-model.js`: 기존 카탈로그 선택 로직을 제거하고 검증된 동적 응답을 표시한다.
- `BeautyAI/api-client.js`: 기존 분석 클라이언트를 유지하며 추천 클라이언트를 별도로 연결한다. `gemini-client.js`, 일반 성분 근거 원본, 기존 판독/설명 프롬프트 원본은 수정하지 않았다.
- `data/recommendation_catalog.json` 삭제, `ai-assets.js`에서 제품 목록 제거. 생성 스크립트·공개 파일 허용 목록·배포/모바일 묶음에 새 공개 모듈을 연결한다. HF 묶음은 README 포함 **10개**, 모바일 공개 웹 자산은 **9개**다.
- `app.py`는 이전 Python 회귀 환경에서 새 공개 JS를 제공하도록 허용 목록만 추가했다. Python 분석 서비스는 바꾸지 않았다.

## ym의 세 파일

`ym`에는 **BeautyAI/index.html·style.css·script.js 세 파일만** 반영한다. 새 추천 모듈과 공유 의존성을 JS 하나로 묶어 별도 모듈 파일 없이 동작하게 한다.

    npm ci
    node scripts/build-ym.mjs ../GlowPick-ym
    node scripts/check_ym_recommendations.mjs ../GlowPick-ym

이전 ym의 독자적인 단일 파일 API 구현은 통합 브랜치의 검증된 분석 연결로 교체된다. 따라서 ym도 현재 탭 내 키 재사용·이동 시 초기화, 통합된 성분 근거/주의 안내, 단계별 API 오류 처리를 사용한다. HTML의 키 안내도 이에 맞춘다. 이것은 이번에 의도적으로 바꾼 기존 팀 코드의 범위다. ym의 다른 파일과 main·mj·ysw·kyoungmin_oh는 변경하지 않는다. 이전 ym README는 세 파일 제한 때문에 수정하지 않는다.

## 검증과 배포 상태

- 웹 자동 테스트 67건: 종류 선택 64개 화장품 조합·모델링팩 4개 경우, 종류별 수, 신제품 예시, 실제 도구 메타데이터와 출처 연결, 상세 링크 없는 후보의 재조회/검색 연결, 스킨/토너 오분류·중복·단종·리뉴얼 불일치·잘못된 URL 거부, 사진 호스트/확장자/두 응답의 주소 일치/로딩 실패, 오류/키 보호, 추천 실패 시 성분 리포트 유지 등을 포함한다. API 응답은 주입한 자료이며 실제 상품을 운영 목록에 등록한 테스트가 아니다.
- Python 회귀 35건, 기존 참조 검증 31건을 유지한다. 로컬·배포·모바일 공개 모듈 허용 목록의 일치도 검사한다. 기존 Gradio/Pandas 의존성의 자원/폐기 경고는 실패와 구분한다.
- ym 묶음은 통합 소스에서 재생성한 세 파일과 일치하는지 검사한다. 운영 묶음에는 검증용 가상 상품/응답을 넣지 않는다.
- 브라우저 화면 검사는 별도 로컬 복사본에서 ‘UI 검사 예시 · Gemini 호출 없음 · 가상 제품’으로 표시한다. 스킨·토너·앰플 각 1개, 모델링팩 단일 선택/해제 후 3개, 390px 가로 넘침 없음 등을 확인했다. 공개 CDN 사진 URL을 별도 시험 자료로 주입해 실제 이미지 로딩(`naturalWidth > 0`)과 카드 배치도 확인했다. 추천 실패 예시에서 카드 0개·성분 결과 유지도 확인했다. 이 검사를 실제 API 사진 주소 획득 성공으로 보고하지 않는다.
- 실호출 첫 `NETWORK`는 추가한 `Api-Revision` 헤더의 CORS 사전 요청 거절로 확인했다(공개 OPTIONS: 포함 시 403, 제외 시 200). 헤더를 제거했고 키는 Google 전용 헤더로만 보낸다. 이후 `INVALID_RESPONSE`와 `LIST_NOT_VERIFIED`도 성공으로 계산하지 않았다.
- 실제 Google HTTP 200 응답에서 스킨/토너 목록 조회 error, 에센스/세럼/앰플 조회 success가 관찰됐다. 성공 페이지에도 상세 링크·이미지 주소가 노출되지 않았고 JSON 인용 주석이 생략됐다. 이 관찰을 바탕으로 목록만 확인한 후보를 명시적으로 구분하도록 보완했다.
- 최종 별도 세럼 시나리오(잘 모르겠음/건조함/세럼 선택/사진 판독 생략)에서 **실제 API 2회로 complete, 토리든 다이브인 저분자 히알루론산 세럼 1개, category_list, productUrl null, imageUrl null**을 받았다. 조회 시각은 `2026-11-12T06:26:58.621Z`다. 현재 목록의 ‘1등수분세럼’ 문구를 건조함에 연결했고 상세 정보는 미확인이다. 이는 모든 종류의 성공·사진 자동 수집·성분 판독부터의 전체 실호출을 입증하지 않는다. 키·원응답·실제 테스트 파일은 Git에 넣지 않는다.
