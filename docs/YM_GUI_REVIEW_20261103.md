## 비교 결과와 수정 이유

### 1. 새 GUI와 API 코드 연결

ym의 script.js에는 GUI와 별도의 Gemini 호출·프롬프트·6행 근거·검증 코드가 함께 있었습니다.
이를 그대로 교체하면 mj의 ai-assets/ai-core/gemini-client와 규격·검증이 이중으로 관리됩니다.
새 script.js는 api-client.js를 호출하도록 연결했습니다. 사진·피부 정보·작업 이름·이번 요청용 키를 기존 명세대로 전달합니다.
기존 모델·프롬프트 버전·6행 근거·요청/응답 구조·엄격한 검사·애니메이션 사진 거부·시간 제한·오류 정제를 유지했습니다.
HTML은 ES module로 불러오며 report-model.js를 공개 자산 목록·로컬 경로·최소 배포 ZIP에 추가했습니다.

### 2. 설명 실패를 성공으로 표시하지 않음

ym의 performAnalysis는 설명 API 실패·출력/근거 검사 실패를 catch하여 needs_evidence로 바꾸고 일반 리포트를 이어 표시했습니다.
needs_evidence는 검토 근거가 없는 상태를 뜻하므로 API/근거 검사 오류와 구분해야 합니다.
mj의 ok=false 처리를 유지하여 설명 단계 오류는 성공 리포트로 표시하지 않습니다.
기존 판독 결과가 메모리에 남아 있어도 성공으로 표시하거나 이전 리포트를 재사용하지 않습니다.

### 3. 근거와 검토 한계 보존

새 GUI에는 일반 기능 설명은 있었지만 출처 링크와 독립 사람 교차검토 미완료 안내가 빠져 있었습니다.
리포트에 실제 선택된 근거ID·출처 링크를 추가하고 analysis.notice·미완료 판독 안내를 유지했습니다.
실제/모의 응답과 임시 프롬프트 표기도 유지했습니다.
출력 검사가 설명 의미·개인 적합성·안전성까지 보장한다는 표현은 사용하지 않습니다.

### 4. 카드의 판단 범위

건조/속건조 고민과 일반 보습 기능을 연결하는 ym의 카드를 유지하되,
서버 규격 검사 후 전달된 정확한 근거ID·성분명·검토 상태까지 일치하는 경우만 표시합니다.
글리세린·판테놀의 일반 보습 기능 참고이며 개인 효과/적합성 판정이 아닙니다.
알란토인 등 일반 컨디셔닝 설명을 임의로 개인 보습 효능이나 주의 성분으로 분류하지 않습니다.
미등록/미확인 항목은 추가 확인으로 표시하고, 정확한 제품 조합 근거가 없어 혼합은 unknown으로 유지합니다.
사용자 금지 선택은 사용자 진술임을 구분해서 추가 안내합니다.

### 5. 키 입력과 결과 복사

새 키 보기/숨기기를 유지하며 요청 시작·성공·실패·새로고침 때 키 입력창을 비우고 표시 상태도 password로 되돌립니다.
없는 사진/키, 잘못된 키, 입력 변경, 탭 변경 시 이전 리포트를 새 결과처럼 보여주지 않습니다.
복사 결과에 판독/설명 상태·원문·재촬영 안내·혼합 미확인·출처·검토 한계를 포함했습니다.
자격 증명 필드는 복사하지 않습니다. 복사 동작은 사용자가 버튼을 누른 때에만 수행합니다.
키보드로 탭을 전환할 수 있도록 ArrowLeft/ArrowRight/Home/End 동작을 추가했습니다.
