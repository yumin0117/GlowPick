# 현재 탭에서 Gemini 키 재사용 — 2026-11-09

사용자의 후속 요청에 따라 매 분석 후 키를 지우던 동작을 변경했습니다.
한 번 입력한 키는 현재 화면의 비밀번호 입력란에만 유지하며 화장품·모델링팩 분석과 오류 후 재시도에 재사용합니다.
요청을 시작하면 보기 토글은 비밀번호 형태로 되돌립니다.
키를 바꾸거나 지우려면 입력란을 직접 수정할 수 있습니다.

새로고침·페이지 이동·탭 닫기 시 키를 초기화합니다.
뒤로 가기 등 페이지 복원 시에도 pageshow에서 지웁니다.
브라우저 저장소·쿠키·URL·서버·로그에는 저장하지 않습니다.
JavaScript 메모리의 완전한 소거를 보장하지 않으며 본인 브라우저의 개발자 도구 등에서 키가 보일 수 있다는 기존 한계는 유지합니다.

## 변경

- BeautyAI/script.js: 요청 시작 시 입력값 삭제 대신 비밀번호 마스킹. 초기화는 로드·페이지 이동/복원 시 유지.
- BeautyAI/index.html: 현재 탭에서 재사용한다는 안내로 갱신.
- README.md, scripts/package_static.py: 배포·사용 안내 갱신.
- tests/key-session.test.mjs: 실제 UI 이벤트 핸들러를 실행하는 오프라인 회귀 시험.
- API 클라이언트는 각 요청에서 전달받은 키만 사용하며 자체적으로 캐시하지 않습니다.
- 디자인·분석 프롬프트·근거·혼합 unknown 처리에는 변경이 없습니다.

pagehide/pageshow 초기화를 확인합니다. API·응답은 테스트 대역을 사용하며 실사용 키·Google 호출은 없습니다.

실제 로컬 브라우저에서도 손상 사진을 두 번 분석한 뒤 같은 키로 모델링팩 탭 요청이
키 누락 안내 대신 이미지 검증 단계까지 도달하는지 확인했습니다.
새로고침 후에는 키를 다시 요구했고 입력란은 password였습니다.
손상 사진은 Google 호출 전에 거부되므로 이 브라우저 시험도 실제 Gemini 호출은 0회입니다.
키 자체나 값을 읽어 로그에 남기지 않고 동작 결과로 확인했습니다.
