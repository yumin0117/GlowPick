복수 고민에는 중복 제품을 한 번만 보여주고 해당 이유를 함께 표시한다. 그 밖의 고민에는 확인된 후보가 없다고 안내한다. 제품명·추천 이유·성분 포인트·유의점·공식 제품 정보 링크가 카드에 나오며, 결과 복사에는 추천 내용과 혼합 안내를 포함한다. 복사 텍스트에는 URL을 넣지 않는다.

추천은 사용자 고민과 제조사가 공개한 제품 정보를 연결한 후보 목록이다. 업로드 제품과의 병용 적합성, 개인별 효과, 제품 간 우열, 여드름 치료 효과를 판정하지 않는다. 추가 Gemini 호출 없이 공개 카탈로그를 사용하므로 모델이 제품명·링크·혼합 비율을 생성하지 않는다.

전성분 미완료·판독 불가·여러 제품·모의 응답·요청 실패에는 제품 추천을 표시하지 않는다. 판독의 `complete` 상태가 OCR 정확성을 보장하는 것은 아니다. 성분의 일반 기능 근거가 없는 `needs_evidence`라도 판독이 완료됐다면, 그 성분 설명과 별개인 제조사 정보 기반 제품 후보는 표시할 수 있다.

모델링팩의 후보는 **해당 팩에 섞어도 된다는 추천이 아니다**. 특정 팩·앰플·버전·조건의 조합 근거가 없으므로 `unknown`을 유지한다. 사용자가 혼합 허용을 체크해도 승인으로 바꾸지 않으며, 혼합 금지를 선택하면 섞지 말라고 명시한다. 제조사가 지정한 혼합액과 사용법을 따라야 한다.

## 브랜치 범위

- 통합 구현·데이터·문서·테스트는 `integration/hf-static-final`에만 반영한다.
- `ym`에는 `BeautyAI/index.html`, `BeautyAI/style.css`, `BeautyAI/script.js` **세 파일만** 반영한다.
- ym의 원래 구조는 JS 하나에 API 구현을 포함한다. 모듈형 통합 JS를 그대로 덮어쓰면 없는 모듈을 요구하므로, 기존 standalone 구조에 같은 추천 카탈로그·선택 함수·뷰만 삽입했다.
- `scripts/sync_ym_recommendations.py ../GlowPick-ym`은 대상 브랜치가 ym인지 검사하고 이 세 파일만 갱신한다. `node scripts/check_ym_recommendations.mjs ../GlowPick-ym`으로 추천 동작의 일치와 원래 ym API 코드 보존을 확인한다.
- ym의 기존 키 입력·성분 근거·오류 처리 방식은 통합 브랜치와 차이가 있다. 이번 ym 반영은 추천 기능에 한정하며 기존 API 구현을 통합 버전으로 교체하지 않았다.
- `main`, `mj`, `ysw`, `kyoungmin_oh`는 변경하지 않는다. main은 팀원의 작업을 모아 나중에 반영한다.
- 이번 작업은 Git 작업 브랜치 갱신이다. Hugging Face 공개 화면과 기존 APK에 재배포하지 않았다.
