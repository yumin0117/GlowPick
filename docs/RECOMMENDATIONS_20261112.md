## 복수 고민의 선택 기준

‘최적’은 **등록된 7개 후보 안에서 아래 기준에 맞는 목록**을 뜻하며, 개인에게 가장 효과적인 제품을 입증했다는 의미가 아니다.

1. 건조함·속건조 등 같은 관리 목적은 중복 계산하지 않는다. 화면의 12개 고민은 위의 5개 관리 목적에 연결한다. 체크 순서·중복·자유 입력 지시문은 순위에 영향을 주지 않는다.
2. 후보 1~3개의 모든 조합을 비교해 선택한 관리 목적을 가장 많이 연결하는 조합을 찾는다. 단순히 일치 수 상위 3개를 고르는 방식으로 특정 고민이 누락되지 않게 한다.
3. 연결 범위가 같으면 추가 확인이 필요한 제품 수가 적은 조합, 올리브영 등록 미확인 제품 수가 적은 조합, 우선·보완 제품 수가 적은 조합 순으로 고른다. 글루코노락톤(PHA) 함유 제품과 건조·민감 고민, 식물 오일 함유 제품과 민감·홍조·열감 고민 등의 조합에는 추가 확인 표시를 사용한다. 민감성 피부 타입 선택도 확인한다. 이는 금기나 위해성을 확정한 판단이 아니다.
4. 고른 조합 안에서 여러 목적에 연결되는 제품을 **우선 후보**, 부족한 목적을 나눠 연결하는 제품을 **보완 후보**로 표시한다. 같은 조건이면 데이터 등록 순서이며 임상적 효과 순위가 아니다.
5. 남는 자리에는 추가 확인 표시가 없는 **대안 후보**를 올리브영 등록 확인 제품부터 넣어 전체 카드를 최대 3개로 제한한다. 일부 목적만 다루는 대안은 그 한계를 표시한다. 등록 미확인 제품에는 미확인 문구를 표시하고 쇼핑 링크를 만들지 않는다. 이 목록은 모든 제품의 동시 구매·병용·혼합을 권하는 루틴이 아니다.

예: 건조함+여드름 → 센텔라 앰플이 보습·진정 두 목적에 연결되어 우선. 건조함+주름 → 펩타이드 부스터가 보습·탄력에 연결되어 우선. 피지+여드름 → 올리브영 등록 확인 센텔라 앰플과 펩타이드 부스터를 우선·보완 후보로 표시. 12개 전체 → 펩타이드 부스터·센텔라 앰플·톤 브라이트닝 캡슐 앰플로 5개 목적을 모두 연결한다. 이들은 제조사 정보와 사용자 쇼핑처 선호에 따른 목록 선택 예시다.

모델링팩의 후보는 **해당 팩에 섞어도 된다는 추천이 아니다**. 특정 팩·앰플·버전·조건의 조합 근거가 없으므로 `unknown`을 유지한다. 사용자가 혼합 허용을 체크해도 승인으로 바꾸지 않으며, 혼합 금지를 선택하면 섞지 말라고 명시한다. 제조사가 지정한 혼합액과 사용법을 따라야 한다.

## 브랜치 범위

- 통합 구현·데이터·문서·테스트는 `integration/hf-static-final`에만 반영한다.
- `ym`에는 `BeautyAI/index.html`, `BeautyAI/style.css`, `BeautyAI/script.js` **세 파일만** 반영한다.
- ym의 원래 구조는 JS 하나에 API 구현을 포함한다. 모듈형 통합 JS를 그대로 덮어쓰면 없는 모듈을 요구하므로, 기존 standalone 구조에 같은 추천 카탈로그·선택 함수·뷰만 삽입했다.
- `scripts/sync_ym_recommendations.py ../GlowPick-ym`은 대상 브랜치가 ym인지 검사하고 이 세 파일만 갱신한다. `node scripts/check_ym_recommendations.mjs ../GlowPick-ym`으로 추천 동작의 일치와 원래 ym API 코드 보존을 확인한다.
- ym의 기존 키 입력·성분 근거·오류 처리 방식은 통합 브랜치와 차이가 있다. 이번 ym 반영은 추천 기능에 한정하며 기존 API 구현을 통합 버전으로 교체하지 않았다.
- `main`, `mj`, `ysw`, `kyoungmin_oh`는 변경하지 않는다. main은 팀원의 작업을 모아 나중에 반영한다.
- 이번 작업은 Git 작업 브랜치 갱신이다. Hugging Face 공개 화면과 기존 APK에 재배포하지 않았다.
