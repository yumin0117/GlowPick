# 추천 제품명 누락과 반복 문구 수정 — 2026-11-12

## 사용자가 확인한 문제와 변경

스킨·토너 선택에서 링크/출처 응답 검사 실패로 추천 영역만 있고 제품명이 0개였다. 기존에는 목록 후보를 찾은 뒤 상세 재조회 실패·엄격한 부가 필드·JSON 주변 설명 때문에 전체 후보가 사라졌다. 제품명 표시를 상세 링크·사진 확인과 분리했다.

- 첫 공식 목록 조회에서 확인한 제품명은 유지한다. 링크·사진·선택 설명 필드는 비어 있어도 제품명을 버리지 않는다.
- JSON 응답 형식을 지정하고, 설명/코드 펜스/인용 문구가 붙어도 완성된 JSON 객체를 읽는다.
- ‘크림 스킨’은 스킨, ‘에센스 토너’는 토너, ‘스킨부스터 세럼’은 세럼으로 마지막 본품 제형을 구분한다. 스킨케어라는 일반 단어, 브랜드 스킨1004, 증정 토너, 스킨밀크, 혼합 세트, 패드·마스크·헤어·바디·메이크업은 해당 종류로 세지 않는다.
- ‘다시 추천 받기’는 사진을 재판독하지 않고 현재 피부 고민/종류로 추천만 실행한다. 재요청 실패도 이미 표시된 제품명을 지우지 않는다.
- `data/reviewed_guidance.json`의 12개 도움 설명에서 ‘개인별 효과와 제품 적합성을 판단한 결과는 아니에요.’ 반복 문장만 제거하고 `ai-assets.js`를 재생성했다. 성분의 근거ID·출처·기능 내용은 유지했다. 요청한 기존 팀 데이터의 표시 문구 변경이다.
- 이름을 사진 위에 표시한다. 사진 주소가 없으면 큰 빈 사진 영역을 만들지 않는다. 실제 이미지가 로딩에 실패하면 사진 안내와 제품명은 유지한다.

## 실제 상품 목록과 제품 선택

**목록 조회 실패를 모델의 기억에 맡기는 시험에서는 실재/브랜드가 의심되는 이름이 섞였다. 이 방식은 폐기했고 운영 코드에 넣지 않았다.**

올리브영 한국 공식 페이지의 스킨케어 판매 랭킹 100행, 스킨/토너 1·2페이지 각 24행, 에센스/세럼/앰플 24행, 로션 24행을 브라우저 DOM에서 수집했다. 임의의 추천 제품을 손으로 고르지 않고 모든 수집 행에 같은 제외/종류/URL 검사를 적용했다. 중복·품절·분류 불명·지원하지 않는 제품을 제외한 **122개**를 `data/retail_listings.json`에 기록했다. 스킨 2, 토너 41, 에센스 4, 세럼 22, 앰플 11, 크림 24, 로션 18개다. 올리브영 전체 재고를 전수 수집한 자료는 아니다.

실시간 목록에서 요청 종류를 채우지 못하면 Gemini에 해당 종류의 실제 상품 ID·이름·브랜드 목록을 제공해 **ID만 선택**하게 한다. 이름·사진·상품 URL은 앱이 공식 목록의 같은 ID에서 가져온다. 모델이 목록 밖 이름/ID를 생성하면 사용하지 않는다. 따라서 7개 등 몇 개의 제품을 추천값으로 고정하거나 모델 기억의 이름을 사실로 표시하지 않는다. 최신 실시간 조회에서 새 제품을 찾으면 수집 자료에 없는 제품도 기존 경로로 추천할 수 있다.

수집 목록은 요청할 때마다 자동 재수집되는 DB가 아니다. 새 상품·단종·리뉴얼을 모두 즉시 반영한다고 보장하지 않는다. 각 카드에 **목록 수집 시각**을 표시하며 가격·재고는 현재 구매 페이지에서 확인한다. 자료를 갱신하려면 같은 공식 페이지에서 새 캡처 자료를 수집한 다음 아래를 실행하고 소스/공개 배포 묶음을 갱신한다.

```
node scripts/import_retail_listings.mjs <captured-official-lists.json>
python scripts/build_static_assets.py
npm run build:ym
```

키·사진은 이 자료에 없다. 이미지 바이너리는 저장하지 않고 공식 CDN URL을 사용한다. 새 서버·유료 검색·Google Search grounding은 추가하지 않았다. 추천은 기존 무료 모델 `gemini-3.5-flash-lite`에서 최대 2회다.

## API가 일시적으로 실패한 경우

성분 분석 뒤 추천 API가 503/네트워크/시간 초과/무료 한도 때문에 완료되지 않아도 수집 목록의 실제 제품명·사진을 유지한다. 이때는 제품명에 표시된 관리 특징과 사용자 고민을 비교하는 방식이고 `selectionMethod: listing_comparison`과 별도 안내로 구분한다. 이를 AI 실호출 성공으로 계산하지 않는다. 429/인증 오류는 자동 재시도하지 않고 유료 전환도 없다. 키 누락·잘못된 입력은 별도 오류를 유지한다.

종류 선택 규칙은 동일하다. 화장품 최대 3종, 모델링팩 최대 1종, 둘 다 선택 사항이다. 선택한 종류마다 서로 다른 제품 1개, 미선택 최대 3개다. 모델링팩 혼합 상태는 unknown/금지 안내를 유지한다.
