# 서버·프롬프트 담당 인계

## 데이터 경로
사용자 사진 → HF OCR 후보 → 응답 형식 검사 → 원문/불확실 구간 사람 확인 → Gemini 설명 → UI.
정답 데이터는 평가에서만 불러옵니다. OCR에 제품명·정답·출처 성분 목록을 넘기지 않습니다. products는 지원 제품 whitelist가 아닙니다. 신규 제품도 사진의 보이는 내용만 읽어야 합니다.

## OCR JSON
```json
{"status":"partial","rawText":"읽힌 부분","ingredients":["읽힌 성분"],"uncertainSpans":["마지막 줄 판독 불가"],"warnings":["목록 일부만 보임"],"nextAction":"전성분 전체를 확대 촬영해 주세요."}
```
status: complete / partial / unreadable / no_ingredients / multiple_products.
complete는 원문과 목록이 있고 불확실 구간이 없어야 함. 판독 불가·목록 없음·다중 제품은 단일 ingredients를 비움. partial은 읽힌 성분만 보존하며 다음 행동을 안내. 예제는 형식 설명이며 실제 제품 관측이 아닙니다.

Gemini 어댑터는 complete와 reviewed=True인 경우에만 전송합니다. 피부 고민은 USER_DATA, OCR은 OCR_DATA로 분리하여 JSON 자료로 전달합니다. 사진·OCR 문자열에 포함된 명령은 실행 지시가 아닙니다. 반환 JSON은 다시 검사하고 UI에서는 글자로 안전하게 표시합니다.

## 평가
- 정규화: NFKC, 연속 공백, 영문 대소문자, 마지막 마침표만 통일.
- 누락·추가: 성분 출현 횟수를 보존하여 비교. 중복을 set으로 없애지 않음.
- 정밀도=일치 수/출력 수, 재현율=일치 수/정답 수. 빈 출력 정밀도는 null, 재현율 0.
- 순서 오류: 최장 공통 부분수열이 일치 성분 수보다 작은지 확인.
- CER=문자 편집거리/정답 문자 수. rawText의 전성분 부분만 평가. CER은 추가 글자가 많으면 1을 넘을 수 있음.
- exact_sequence와 status가 모두 일치해야 pass_all. 재현율 100%만으로 통과 처리하지 않음.
- 정답 없는 광고·사용법은 성분 점수 제외. 상태 판정과 '없는 성분 생성 여부'를 별도 검토.
- 현재 JSON 파싱 오류와 잘린 응답은 error로 저장. 임의 JSON 수리로 성공 처리하지 않음.

## 분할
P003/P004/P005 development, P006 holdout. 같은 원본의 크롭/변형은 같은 분할. I004에 P006도 노출되므로 I004 전체를 프롬프트 조정에 사용한 경우 P006은 더 이상 독립 holdout이 아닙니다. 현재 4제품의 작은 자료는 통계적 성능 일반화에 부족합니다. 최종 성능 평가는 별도 신규 제품 사진으로 수행하세요.

## 통합 협의점
2026-10-31 확인: main은 문서 중심, PR #1은 UI 프로토타입. 확정된 실제 백엔드 계약은 확인되지 않아 본 문서는 제안 규격입니다. 기존 /analyze 같은 경로가 이미 있다고 가정하지 않습니다. 서버 담당이 이미지 업로드 endpoint·용량·CORS·오류 코드를 정한 뒤 연결합니다. Static Space는 Python을 실행하지 않으므로 서버가 별도로 필요합니다. Gradio Space 검증 앱을 기존 HTML 화면으로 교체했다고 간주하지 마세요.

혼합 판단은 해당 제품·버전 조합의 제조사 지침이 확인되지 않아 unknown을 유지합니다. I005 광고의 '10배'를 검증 효능으로 전달하지 않습니다. 성분 설명·피부 적합성은 OCR 정확도 시험과 별도 근거 검증이 필요합니다.
