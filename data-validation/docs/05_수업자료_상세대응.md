## 과제 조건
안내 PPT: 배운 기술 2개 이상, 실제 화면 시연, 학생 결제 0원·결제 계정 연결 금지, 개인정보·API 키 비공개, 각자 자기 역할 설명. HF 모델 + Gradio/Space + Gemini 흐름으로 맞췄습니다. 현재는 코드·실험 틀을 마련했고 실제 모델·API·배포 시연 검증은 남았습니다.

1007과 1014의 팀프로젝트 안내는 발표 순서/제출 주차 표현이 다릅니다. 역할분담 PDF도 다른 시점의 일정이 있으므로 특정 날짜를 새로 만들어 확정하지 않았습니다. 실제 Teams 공지와 교수님 최신 안내를 기준으로 하세요.

## 팀 문서 간 차이
킥오프 문서는 HF OCR→Gemini→Gradio를 요구하며 국내/해외 라벨 10~15장 수집을 제시합니다. 역할분담 PDF는 Gemini+Static Space를 기본안으로 두며 전성분 담당에게 사진-정답·출처·오류 기록을 요구합니다. 현재 GitHub README는 HTML/CSS/JS UI 및 향후 서버 연동을 설명합니다. 따라서 기존 프론트엔드를 바꾸지 않고 별도의 데이터 검증 폴더를 인계하도록 했습니다.

## 모델 선택 근거와 한계
Qwen/Qwen2.5-VL-3B-Instruct를 국문·영문 사진 판독의 실험 후보로 선택했습니다. 공식 카드의 AutoProcessor/생성 방식에 맞추었으나 한국어 화장품 성분 정확도를 입증한 것은 아닙니다. TrOCR base printed는 단일 인쇄 텍스트 줄 중심의 후보여서 다단 한국어 라벨의 기본 모델로 선정하지 않았습니다. 더 큰 모델·유료 API로 자동 대체하지 않습니다. 무료 Colab GPU가 없으면 실험을 중단하고 미실행으로 남깁니다.

라이브러리 호환성은 수업의 최신 -U 설치를 그대로 반복하는 대신 HF OCR에는 transformers 4.51 이상 5 미만 범위를 사용합니다. 이 패키지에서 지정한 범위는 실제 설치 검증 완료 잠금파일이 아닙니다. Colab 실행 결과에 버전을 저장합니다.

추가 자료 challenger는 두 봇의 독립 history, 역할별 시스템 프롬프트, 실패 시 기록 유지, JSON 심판 응답을 다룹니다. 두 모델의 동의가 전성분 사실 검증을 대신하지 않으므로 이번 정답 확정에는 사용하지 않았습니다. 카톡 캡처에서는 main 대신 개인 브랜치 사용 요청과 21/25/28/30일 일정이 보이지만 월은 확인할 수 없어 달력 날짜로 확정하지 않았습니다.
